这里我还建议你对 Cursor 的 Phase 2 结果重点盯 **4 个验收点**：

1. **把 `E:\Ollama` 拔掉/改名后，程序仍然能正常启动。** 这证明没有偷偷硬编码。
2. **系统 Ollama 已经在 11434 运行时，再启动 bundled Ollama，两者能同时存在。**
3. **关闭 PDF2Typora 后，系统的 Ollama 还活着，而软件自己启动的 11435 被关闭。**
4. `/api/show` 返回没有 `vision` 的模型时，不能让它进入 PDF Vision 模型下拉框。

Ollama 的官方 API 现在还支持结构化输出，而且图像可以和文本一起提交，所以等 Phase 2 跑稳之后，Phase 3/4 我会建议你不要再走“模型返回一大坨 Markdown，然后 Python 猜里面有什么图”的路线，而是正式设计成：

```text
Vision
↓
JSON Schema
├── markdown
├── figures[]
├── warnings[]
├── continuation
└── confidence
```

这样后面“自动找图、自动裁图、跨页续接、异常页 Review”会好做很多。Ollama 官方当前的 Generate API 本身支持 `images` 和 JSON Schema 格式输出，Vision 与 structured outputs 都是正式能力。([Ollama][2])

等 Cursor 按这份把 Phase 2 跑完，把它的**实际模型列表、Ollama 版本、pytest 结果和 `E:\Ollama` 检测结果**贴回来，下一步就可以开始做真正的 **Phase 3：PDF 高质量页面渲染 + 页面预览 + DPI/页码范围/缓存**。
