现在开始直接修改：

中的真实项目文件。

有一个地方你之后拿 Cursor 的报告回来时，我会特别检查：**“第二次渲染 8 页全部缓存命中”**。这个测试比“成功生成 8 张 PNG”更重要，因为你的最终目标是几百页教材、可能处理几个小时乃至多次修改 Prompt。如果缓存和断点机制不稳，以后每次修改一点东西都重新跑整本书，会非常痛苦。

另一个关键点就是这次新增的 `page_stage_states`。之后一页的状态就可以自然变成：

```text
Page 037
├─ render       SUCCESS
├─ transcribe   SUCCESS
├─ figures      NEEDS_REVIEW
├─ clean        WAITING
└─ validate     WAITING
```

这样等我们做到最后“一键全自动”时，Pipeline 才真正知道**应该从哪一步继续，而不是只知道这页到底算 SUCCESS 还是 FAILED**。

等 Phase 3 报告回来，下一阶段就会非常有意思了：**Phase 4 不做整本批处理，先只做一张页面图片 → 本地 Vision → 严格 JSON Schema → Markdown**。我们会拿你机器上的 4060 8GB 实测 2～3 个本地视觉模型，然后再决定最终默认模型，而不是现在凭模型参数拍脑袋选。
