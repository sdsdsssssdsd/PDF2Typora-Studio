### 这次我会重点看什么

最关键的已经不是自动率，而是 **4 个 Figure 能不能真正从 Review 走到终态**。如果最后变成：

```text
4 Figures
├─ 1 safe marker repair
├─ 1 candidate accept
├─ 2 manual crop/placement
└─ 0 unresolved
```

那就已经足够进入下一阶段，因为程序已经具备“自动能做就自动、自动不确定就人工、人工做完还能继续流水线”的完整闭环。

另外，**marker 语法漂移和 marker 缺失要严格区分**。像：

```text
FIGURE page=4 index=1
```

其实信息都在，只是格式错了，这种完全值得程序安全归一化；但“JSON 说有图、Markdown 里压根没有任何标记”就不能猜，因为真正危险的不是裁错图，而是**把正确图片插进错误段落**。

等 Phase 6.5 回来，只要出现：

```text
Figure Readiness = READY
Needs Review = 0
Failed = 0
```

下一阶段就可以正式做 **Phase 7：`resolved_pages` 顺序合并 → continuity 边界检查 → `raw.md`**。Cleaner 仍然建议再晚一阶段，让“忠实转录”和“格式纯化”继续保持隔离。
