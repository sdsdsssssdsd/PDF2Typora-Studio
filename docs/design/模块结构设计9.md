这轮测试我建议重点看两个不同层面的结果。

第一是 **Phase 9 本身必须接近“无聊”**：`clean.md → final.md → export` 不应该发生任何文字变化。最漂亮的结果就是三个 Markdown 的内容关系非常明确：

```text
raw.md
   ↓ Cleaner
clean.md
   ↓ 只验证、冻结
final.md   ← 与 clean.md SHA256 完全相同
   ↓ 只复制
导出的“书名.md” ← 与 final.md SHA256 完全相同
````

第二是你提出的这个 PDF 非常适合做第一次真正的 **fresh E2E 回归**。这次尤其不要只看最终有没有 `final.md`，还要让 Cursor 统计“**到底人工介入了几次**”。如果 Fresh E2E 最终显示主要人工工作都集中在 Figure Placement，那么下一阶段就知道该优化 Figure Locator，而不是再折腾已经稳定的 Render、Cleaner 或 Export。

等 Phase 9 跑完，如果 `clean.md = final.md = exported .md` 三个 SHA256 一致，而且第二轮 E2E 的真实 Vision 调用接近 0，那么核心软件流水线就基本封顶了。下一阶段才值得开始做 **Phase 10：PyInstaller + 项目内置 Ollama + Portable 目录 + 一键启动 EXE**。
